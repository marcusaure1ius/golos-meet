# Golos Meet — продуктовый вижн

Обновлено: 12 ноября 2026. Статус: принят пользователем.
Единый источник продуктовой воли. При расхождении других документов
(`DEVELOPMENT_PLAN.md`, issues, `CLAUDE.md`) с этим документом приоритет имеет он,
пока пользователь не изменит его. Изменения — только по явным решениям пользователя
с датой в разделе «История решений».

## 1. Суть

Golos Meet — записывальщик встреч, превращающийся в **личную базу знаний о проектах**:
«аля супер Obsidian». Записи встреч перестают быть отвязанными файлами — они
распределяются по проектам, пополняют накопительный контекст и отвечают на вопросы
с источниками. Документы (Word, PDF, PNG, текст) добавляются в тот же контекст.
Постепенно через приложение можно дойти вплоть до создания и ведения задач.

Проблема пользователя, которую решает продукт: встречи записаны, но чтобы понять,
о чём договаривались раньше, приходится вручную искать по календарю, Outlook и ленте
приложения. Контекст проектов должен копиться и быть доступным вопросом.

## 2. Сценарии

### 2.1 Запись встреч
- Встречи идут в Контур.Толк; под каждую встречу создаётся своя ссылка — ручного
  списка комнат нет. Участие пользователя определяется автоматически (#72).
- Запись двух дорожек, локальная расшифровка, конспект и action points.
- Индикация записи в строке меню Mac: длительность и состояние захвата (#3).
- Ручной старт/стоп записи для встреч вне Толка — в объёме финала.
- Один Mac — осознанное допущение; API не доказывает устройство.

### 2.2 Проекты
- Древовидная структура проектов «как в Obsidian» (полновесное дерево — часть
  UI-этапа #18/#19; до редизайна — плоский список/группы).
- Встречи распределяются по проектам автоматически по смыслу; при низкой
  уверенности остаются во Входящих с понятным предложением.
- Ручные исправления приоритетны и не перезаписываются автоматикой.
- Одна встреча может относиться к нескольким проектам без копирования записи.

### 2.3 База знаний
- Документы добавляются в контекст проекта и индексируются; поиск объединяет
  встречи и документы и ведёт к странице или таймкоду.
- **Для первого релиза индексация (эмбеддинги) выполняется внешними моделями**
  (решение 12.11.2026). Следствие: содержимое фрагментов уходит внешнему сервису,
  поэтому индексация подчиняется тому же per-project согласию, что и генерация.
  Возврат к локальной индексации — отдельными тасками пользователя.
- Локальная расшифровка речи остаётся локальной (модель STT скачивается при
  первом запуске).

### 2.4 Вопросы и память
- Вопросы по проекту — локально отобранный контекст, ответ с проверяемыми
  источниками; честное признание недостатка данных.
- Накопительная память проекта: решения, договорённости, изменения сроков,
  открытые вопросы. Обзор проекта обновляется после каждой встречи; каждый вывод
  проверяется по источнику; история не теряется, ручные правки не затираются.
- Панель контекста проекта доступна во время встречи. Полный MVP: обзор,
  история, источники и зависимости, ручные исправления/отмена, очередь,
  показ полного контекста перед разовым согласием.
- Statement о выполненной работе — событие памяти, а не автоматическое закрытие
  задачи («я не говорю, что мы action points выполнили»).

### 2.5 Задачи (Constance)
- Создание, подтягивание и обновление задач связано с договорённостями встреч —
  **в объёме финала** (решение 12.11.2026 снимает отложенный статус #6).
  Автоматическое закрытие задач — только отдельным правилом.

### 2.6 Дистрибуция
- Аудитория — свой круг: человек с таким же Mac запускает приложение, скачивает
  локальную модель STT, подключает свой ключ OpenRouter.
- Упаковка минимальная (ad-hoc/Dev ID, без нотаризации); основной сценарий —
  бандл + download-on-first-run модели.

## 3. Принципы

1. **Единая заменяемая модель.** Модель генерации одна и настраивается в одном
   месте — применяется ко всем LLM-компонентам: конспекты, вопросы, память (#80).
   Текущий дефолт — DeepSeek V4.1 Flash; при выходе более сильных моделей
   переключение должно быть лёгким.
2. **Согласие на облако — per-project.** Отправка материалов и производной памяти
   во внешние сервисы разрешается отдельным выбором для каждого проекта,
   по умолчанию запрещена; действует для генерации и внешней индексации.
3. **Локальное — по умолчанию.** Запись, расшифровка, хранение оригиналов,
   история и журнал памяти — на Mac. Исходные записи и документы сохраняются;
   обзор пересобираем из источников.
4. **История не теряется.** Ручные исправления приоритетны, конфликты сохраняются
   со ссылками, у каждого вывода есть проверяемый источник и дата.
5. **Замер производительности не маскируется.** Состояния «неизвестно»/«ошибка»
   не выдаются за «встречи нет» или «готово».
6. **Проверка пользователем — в изолированной копии.** Agent-тестирование —
   только в приложении Golos Meet QA (#67/#68); рабочая версия не используется
   для автоматических проверок.

## 4. Не входит

- Интеграция с календарём (исключена пользователем 30.10.2026).
- Вебхуки и сервер-приёмник Толка; ключ пространства (доступен только PAT).
- Живая потоковая ASR и подсказки по незавершённому разговору — следующий этап
  после панели памяти.
