# Задачи Golos Meet

Подход адаптирован из `creating-github-issues` проекта Нейроюрист. Процесс и правила Git — в `AGENTS.md`; не переносить чужие доски, людей, сроки или поля.

- Репозиторий задач: `marcusaure1ius/golos-meet`. Проверь текущий remote и существующие issues, включая закрытые, чтобы не создать дубликат.
- Опиши проблему и наблюдаемый результат для читателя без истории чата. Не выдумывай сроки, ответственных, подтверждённые права API или статус готовности.
- Обязательные части: контекст, что сделать, проверяемые критерии готовности. При необходимости добавь зависимости с точными номерами, ограничения, ссылки на версионируемые документы.
- Один issue — проверяемый результат. Большой этап может быть родительской задачей с небольшими связанными issue и PR. Не дробить механически по файлам.
- Явное поручение пользователя организовать workflow или завести задачи разрешает создание issues в этом объёме; повторное подтверждение не требуется. При неоднозначном содержании сначала уточни существенный пробел.
- Предпочитай подключённый GitHub-инструмент. Для `gh` передавай описание файлом через `--body-file`, сохраняя настоящие переводы строк.
- Рабочая ветка этапа начинается от актуального `origin/codex/product-preview` после fetch; PR направляется в `codex/product-preview`. Каждый PR требует независимого ревью конкретного head SHA. По разрешению пользователя координатор объединяет только проверенные изменения в preview; ревьюер не сливает PR.
- Зависимость закрыта после проверки GitHub, независимого ревью и принятия проверенного кода в preview; merge в `main` не требуется. Проверь PR, проверенный SHA и наличие результата в preview. Папка в чужом worktree, статус issue или сообщение автора не заменяют это. Согласованные статусы issues обновляет координатор.
- Активны этапы 1–4, Constance (#6) отложен, календарная интеграция исключена. Запуск по зависимостям разрешает чат «Координация · Golos Meet». Любую существенную неясность уточни у пользователя до зависимых действий; понятную независимую работу продолжай.
- `main` остаётся неизменным до общей ручной проверки продукта. Итоговый [PR #8](https://github.com/marcusaure1ius/golos-meet/pull/8) из preview в `main` остаётся draft и требует отдельного явного разрешения пользователя после проверки всего продукта; auto-merge не включать.
- В конце дай ссылку на issue. Новому чату передай номер, область работы, зависимости, обязательные документы, базу `origin/codex/product-preview`, target PR `codex/product-preview` и понятную команду начала. Не передавай ключи и пользовательские материалы.

GitHub — единственный трекер. Agent Board и `projects-control-work` запрещены.
