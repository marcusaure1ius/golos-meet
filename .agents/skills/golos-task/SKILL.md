# Задачи Golos Meet

Подход адаптирован из `creating-github-issues` проекта Нейроюрист. Процесс и правила Git — в `AGENTS.md`; не переносить чужие доски, людей, сроки или поля.

- Репозиторий задач: `marcusaure1ius/golos-meet`. Проверь текущий remote и существующие issues, включая закрытые, чтобы не создать дубликат.
- Опиши проблему и наблюдаемый результат для читателя без истории чата. Не выдумывай сроки, ответственных, подтверждённые права API или статус готовности.
- Обязательные части: контекст, что сделать, проверяемые критерии готовности. При необходимости добавь зависимости с точными номерами, ограничения, ссылки на версионируемые документы.
- Один issue — проверяемый результат. Большой этап может быть родительской задачей с небольшими связанными issue и PR. Не дробить механически по файлам.
- Явное поручение пользователя организовать workflow или завести задачи разрешает создание issues в этом объёме; повторное подтверждение не требуется. При неоднозначном содержании сначала уточни существенный пробел.
- Предпочитай подключённый GitHub-инструмент. Для `gh` передавай описание файлом через `--body-file`, сохраняя настоящие переводы строк.
- Зависимость закрыта только после проверки GitHub и интеграции результата. Папка в чужом worktree или сообщение автора не заменяет это.
- В конце дай ссылку на issue. Новому чату передай номер, область работы, зависимости, обязательные документы и понятную команду начала. Не передавай ключи и пользовательские материалы.

GitHub — единственный трекер. Agent Board и `projects-control-work` запрещены.
