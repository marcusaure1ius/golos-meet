# Ревью Golos Meet

Подход адаптирован из `reviewing-branch` проекта Нейроюрист: проверять поведение и поток данных, а не только diff. Для процесса прочитай `AGENTS.md`.

## Контекст

1. Прочитай issue, описание PR, проверяемый head SHA, результаты проверок и связанный раздел `DEVELOPMENT_PLAN.md`.
2. Установи base по фактической ветке PR; изучи весь diff и потребителей изменённых контрактов. Наличие кода не означает, что он подключён к приложению.
3. Независимый ревьюер работает в отдельном контексте и worktree. Не исправляй ветку автора, не коммить и не сливай PR. Самопроверка автора полезна, но не заменяет независимое ревью.

## Проверка поведения

- Запись: готовность дорожек, ошибка старта, завершение/краш/сон, mute/тишина, несколько устройств, асинхронные события, сохранность аудио.
- Толк: PAT и ключ пространства, права и доступный метод. Недоступность API не равна отсутствию встречи. Ключ не попадает в URL, лог или другой origin.
- Документы: локальность извлечения/OCR/эмбеддингов, лимиты ресурсов, отмена, страницы/таймкоды, версии и дедупликация. Повторная индексация не уничтожает оригинал.
- Память и RAG: область проекта, модель/размерность векторов, актуальность источников, действительные ссылки, история и ручные исправления.
- Облако: весь путь до транспорта, включая общие источники нескольких проектов, производные конспекты и разовое согласие. Текст источника не становится инструкцией модели.
- Constance: внешние ID, повторная доставка и статус как источник истины. Заявление на встрече не равно закрытию задачи.
- Тесты: сценарий действительно выполняется; мок, синтетический эксперимент и живая интеграция различаются. Для UI посмотреть реальный экран и состояния.

## Результат

Коротко опиши проверенное поведение и SHA. Замечание содержит серьёзность, точное место, механизм ошибки, последствие и направление исправления. Не блокируй PR вкусовыми замечаниями и не выдавай догадки за баги.

Заверши вердиктом: нужны исправления / существенных замечаний нет, и перечисли непроверенные сценарии. После новых коммитов вердикт не распространяется автоматически на новый SHA.

Результат по умолчанию сообщается в чате ревью. Публикация GitHub-комментария или review — только при явном поручении пользователя. Слияние выполняет пользователь.
