# Автоматическое определение текущей комнаты (#72)

Режим предназначен для проверки участия без заранее заданных комнат. Он читает
текущий документ нативного Толка и проверяет присутствие подтверждённого
пользователем аккаунта через PAT. Это диагностический режим: `AppCoordinator`
публикует статус в настройках и меню, но не передаёт его в `Recorder`.

## Чтение нативного клиента

`TalkNativeRoomSource` выбирает только процессы с bundle ID `kontur.talk`.
Через macOS Accessibility читаются окна, обёртки дерева, роль `AXWebArea` и её
`AXURL`. Внутрь документа обход не входит: текст встречи, ссылки истории/чата,
содержимое форм и участники из интерфейса не собираются. Screen Recording,
микрофон, cookies и session tokens для этого механизма не используются.

Нужно отдельно выдать Golos Meet разрешение «Универсальный доступ». Код только
проверяет наличие доступа, не показывает системный запрос автоматически и не
меняет права. Ссылка в настройках открывает соответствующий раздел macOS.
AX-вызовы выполняются вне main thread, последовательно, без наложения поколений.
Обход ограничен 4 процессами, 16 окнами, 2000 узлами, глубиной 16 и временным
бюджетом около 2 секунд; у сообщений AX задан timeout 0,15 секунды. Эти проверки
ограничивают работу, но не являются гарантией реального времени со стороны ОС.

Недоступные/пустые деревья, ошибки и исчерпание лимита означают `unknown`.
Полное отсутствие процесса имеет отдельный результат `notRunning`. В test host
source возвращает `unknown` до обращения к процессам, Accessibility или UI.

## URL и API

Сохранённый HTTPS-origin обязателен. В запрос попадает только room ID из одного
сегмента текущего URL. Origin нормализуется; credentials в URL, другой host/port,
encoded path, вложенные пути и traversal не принимаются. Query/fragment
отбрасываются в памяти и не хранятся/не логируются. Главная страница и известные
служебные страницы не становятся комнатами. Нераспознанный документ даёт
`unknown`, а не подтверждённый выход.

В ID поддержаны строчные латинские буквы, цифры и `_`, до 128 байт. Подчёркивание
проверено живым read-only запросом ранее и покрыто транспортной регрессией (#71).
`TalkAPIClient` по-прежнему использует ephemeral session, заголовок X-Auth-Token,
запрет redirects и общий `TalkRequestBudget` (до 30 запросов/минуту на origin).

`TalkAutomaticObserver` проверяет `userInfo.key` подтверждённого аккаунта, а не
имя, число участников или conference `uniqueId`. Допущение пользователя — звонки
только с этого Mac; API сам по себе не доказывает устройство.

Текущие комнаты объединяются с ранее обнаруженными, пока полный отрицательный
API-цикл не подтвердит выход. Это позволяет проверить выход после исчезновения
окна, в том числе если другие участники остались. Неопределённые циклы сохраняют
кандидатов. Любая ошибка цикла доминирует над частичным положительным ответом.
Всего допускается до 10 кандидатов; при переполнении статус остаётся неизвестным,
пользователь может закрыть лишние окна и перезапустить определение.

Интервал — 10 секунд после цикла, свежесть — 30 секунд по монотонным часам.
Потеря AX/API, 401/403/429, отмена, старый ответ и долгий цикл не выдаются за выход.
Смена настроек, сон и quit инвалидируют поколение. Новый цикл не начинается,
пока не завершился старый, даже если источник/транспорт игнорирует отмену.

В системный журнал пишутся только смены `present`/`absent`/`unknown` с признаком
diagnostic only. Адреса, ID комнат и пользователей, ключи и тела ответов не пишутся.

## Настройки и совместимость

Новый режим включается явно после сохранения ключа и подтверждения аккаунта.
Ручной список в новом UI не требуется. Выбор хранится в отдельном
`talk-automatic-discovery.json`: отсутствие файла сохраняет поведение старой
установки; `false` означает явно выключенный диагностический режим и не включает
старый детектор. Повреждённый файл останавливает автоматизацию.

Прежние настройки комнат не удаляются. Если ранее была полноценно настроена
API-автозапись, UI сообщает об этом и предлагает явно перейти в режим без записи.
После выбора нового режима старое значение API-автозаписи не используется.
Потеря ключа/подтверждения не возвращает старый режим. Обычная ручная запись
остаётся отдельным действием пользователя; диагностика её не запускает.

## Проверка и пределы

Synthetic тесты проверяют обход без чтения содержимого документа, URL/identity,
prejoin → muted/present → absent при оставшихся участниках, потерю источника и
сети, частичные/устаревшие ответы, поздние поколения, лимиты и sleep-wake.
Отдельный production-coordinator тест подтверждает нулевые вызовы аудиодорожек,
отсутствие папок записей и отсутствие legacy fallback в новом режиме.

Нативные NSHostingView-рендеры доступны через
`TEST_RUNNER_GOLOS_MEET_RENDER_TALK_SETTINGS=1 make check`: checking, permission,
unavailable, present, absent, API-error и no-account в обеих темах.
Preview-hosts в research используют in-memory stores и заблокированный native
source; они не являются живой проверкой.

До этой реализации вручную подтверждена доступность URL предпросмотра, muted
звонка и главной страницы после выхода в одной комнате Толка 3.7.0.183393; API
показывал 0 → 1 → 0 участников. Это не проверка данного production source.
Нужно отдельно проверить новую случайную ссылку, права самого Golos Meet,
несколько/свёрнутые окна, PiP, сетевое переподключение, сон и обновление клиента.
Текущая версия не обещает надёжность этих непроверенных сценариев и не включает
новый механизм в автоматическую запись.
