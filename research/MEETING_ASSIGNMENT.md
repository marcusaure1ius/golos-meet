## Решения и контекст

Schema v5 расширяет `meeting_decisions`: origin `manual` / `automatic` / `proposal`, уникальное поколение, JSON объяснения. Перестраиваются родительская таблица и M:N ребёнок в прежнем BEGIN IMMEDIATE с включёнными FK. Существующие ручные решения, включая строки без связей (явные Входящие), копируются. Документы, версии, фрагменты, векторы и аудио миграция не меняет. `busy_timeout`/retry не менялись.

`assignMeeting` всегда сохраняет manual и новое поколение, удаляет прежнее автоматическое объяснение и заменяет полный набор связей. Нет строки решения — ещё не ручной выбор. Пустое manual-решение — устойчивый запрет автоматического назначения. Сервис не снимает этот запрет при reindex/restart/смене модели.

Контекст проектов — только непосредственно назначенные документы и **вручную** назначенные встречи. Auto/proposal-встречи не обучают следующие назначения. Общие источники/аудио не копируются. Дочерние/родительские проекты не наследуют связи. Переименование, изменение дерева/политики/владельцев и ручные изменения меняют durable assignment epoch (в том числе A→B→A).

Ожидаемые источники контекста читаются из связей отдельно от поискового каталога: повреждённая ручная расшифровка, удалённая из индекса, не исчезает незаметно из сравнения. Если ожидаемый контекст отсутствует, ждёт модели/очереди, отменён или содержит ошибку, расчёт завершается явным `notReady`, без частичного уверенного назначения.

## Правило v2

Используются готовые нормализованные passage-векторы одной активной модели/размерности. Для каждой пары фрагментов встречи и доверенного контекста считается cosine; у нескольких окон сохраняется наиболее сильное подходящее основание. Это точное сравнение, без LLM, нового encoder или сети.

Автоматическая связь требует одновременно:

- cosine не ниже **0,90**;
- нормализованное полное имя проекта присутствует отдельными словами в обоих сравниваемых фрагментах, суммарно не короче пяти символов; это имя уникально среди проектов;
- в реплике нет слов `не`, `нет`, `чужой`, `отменён`, `отменен` (консервативная проверка, не русский синтаксический анализатор);
- преимущество не менее **0,04** над лучшей близостью к любому другому проекту **для того же фрагмента встречи**, включая конкурентов ниже порога предложения.

Проекты оцениваются независимо: разные реплики одной встречи могут уверенно назначить её нескольким проектам. Совпадение названия без подходящего контекста не назначает проект. Одинаковые имена в разных ветвях дерева и недостаточно различимый общий контекст приводят к предложению.

Если cosine ≥ 0,90, но правило автоматического выбора не выполнено, сохраняется основание-предложение без связи. При отсутствии таких оснований предлагается тема из первых 100 символов проверенного текста встречи; проект сам не создаётся. Это заготовка для редактируемого предложения UI, не генерация названия. При отсутствии уверенных связей встреча остаётся во Входящих. Возможна смесь auto-связей и предложений к остальным проектам.

Cosine/порог/разница — эвристики, не вероятность. Название обязательно для автоматики: перефразирование без названия может остаться предложением/новой темой даже при настоящем соответствии. Одно отрицание отключает авто-правило для всей реплики; склонение названий и сложные отрицания полноценно не разбираются. Нельзя переносить качество коротких synthetic примеров на архив.

Пределы одного расчёта: 200 проектов, 2000 векторных окон, 100 000 операций сравнения/обработки владельцев. Превышение завершает расчёт явным `limited`, не публикует усечённое решение. Загрузка каталога пока общая; большие архивы не измерены.

## Актуальность, отмена и повтор

План сохраняет весь checkpoint: проекты, decision generations/origins, полный каталог источников/jobs/владельцев и durable model epoch. До вычислений читаются файловые identities; SHA-256 управляемой копии или fingerprint/фрагменты расшифровки сверяются принятым reader. В конце prepare и перед commit повторяются чтение, общий проход identities и проверки DB/model. Symlink, подмена, filesystem ABA/recreate, другая версия/поколение индекса отбрасывают старый план. Ошибка/отмена не записывает решение.

Транзакция commit повторно сверяет весь checkpoint и manual-origin непосредственно перед изменением связей. Поздний worker не перезаписывает ручное M:N или явные Входящие. Конкурирующие планы сериализуются assignment epoch. Идентичный пересчёт возвращает unchanged, не меняет поколение и не создаёт цикл обновлений. Сохранённое объяснение содержит обе версии/chunks/локации основания, modelID/размерность/epoch, файловые stamps, имена проектов, cosine и ближайшего конкурента. UI следующего PR обязан проверять их актуальность перед показом/открытием.

FS и SQLite не образуют общей транзакции: внешняя запись после последней файловой проверки остаётся возможной. Абсолютная атомарность не обещается. Сервис проверяет подготовленный снимок; последующий пересчёт/открытие должен повторять проверку. При notReady/error/limited сервис не снимает прежние auto-связи; отображение их актуальности и повторный запуск после восстановления — часть следующего production/UI PR.

## Настройка и итоговая оценка с настоящей E5

Начальный v1 требовал имени и cosine ≥ 0,90 без сравнения конкурентов; порог предложения был 0,78. На calibration (4 сценария) верны обе ожидаемые связи. Первая evaluation (12) нашла **одну ложную связь**: в тексте с именем «Орбита», но складской темой «Янтаря», cosine к Орбите 0,9191 оказался достаточно высоким. Исторические `v1-corpus.json`, `v1-calibration.json`, `v1-evaluation-found-false-link.json` сохранены с исходными SHA/измерениями. Это не скрытый удачный-only эксперимент.

После исправления v2 сравнивает конкурентов и использует порог предложения 0,90. Прежняя evaluation стала regression и участвовала в разработке. Дополнительно составлены 12 новых evaluation-примеров с другой формулировкой; при их оценке правило/пороги уже зафиксированы. Наборы authored synthetic, четыре тех же проекта (два различных контекста и два проекта с одинаковым именем), короткие реплики. Они не внешний слепой benchmark и не оценка открытого мира.

В evaluation положительны три встречи (одна M:N), остальные девять ожидают отсутствие автоматических связей: несоответствие имени содержанию в обе стороны, отсутствие имени, общие слова, одинаковые имена, отрицание, новая тема, совпадение имени с магазином и разговор без предмета. Проверены фактическая запись связей, unchanged-повтор и manual Inbox после повторного открытия SQLite. Русские формулировки/полные score traces сохранены в JSON.

Финальная evaluation: cold runtime + индекс 16 источников **1,199 с**; медиана prepare+commit **7,91 мс**, максимум 12 наблюдений **8,67 мс**; пиковый CLI RSS **1 864 351 744 байт**. Apple M4 Pro/24 ГБ/macOS 27.0.1, Debug/Onone, CPU E5 из принятого runtime; диск/кэши ОС не сбрасывались. Время не включает повторный unchanged-прогон и ручной override; индекс измеряется отдельно. App RSS, UI latency, большой архив и одновременный живой звонок не измерены. 2–3 реальных проекта ждут явного выбора материалов пользователем.
