# dsh-спайк над QA-архивом Golos Meet (issue #94)

Спайк: поднять DeepSeek Harness (dsh) локально и написать поверх него два
агентных инструмента над QA-архивом (176 реальных встреч), чтобы решить,
продолжаем на dsh или форкаемся. Сценарий-критерий: вопрос «о чём договорились
по прайсингу за ноябрь?» — ответ агента с цитатами и таймкодами из архива.

## Что здесь

| Путь | Назначение |
| --- | --- |
| `package.json` | пиновка `@deepseek-ai/dsh` версии **0.2.2-rc.1** (npm, MIT, developer preview) |
| `plugins/golos-qa/index.js` | dsh-плагин с двумя инструментами: `search_meetings`, `summarize_meeting` |
| `dsh-patch.yml` | оверлей web-профиля: регистрация плагина, персона «отвечай по-русски, сразу с содержимого» (#103), модель OpenRouter `deepseek/deepseek-v4.1-flash`, отключение телеметрии, контракт «только golos-инструменты» (#119) |
| `run-web.sh` | запуск web UI dsh (порт 3080) с ключом OpenRouter из QA-Keychain |
| `test/mock-llm.mjs` | локальный OpenAI-совместимый стриминговый mock-LLM для e2e без ключа |
| `test/dsh-patch.mock.yml` | тестовый оверлей: маршрут openrouter → mock + та же персона + те же отключения инструментов (#119) |
| `test/e2e-mock.sh` | e2e-проверка обоих инструментов, системной инструкции и состава каталога инструментов через mock |
| `test/profile-contract.sh` | тест контракта профиля (#119): в собранном дереве отключены все встроенные инструменты, пресеты — только инфраструктурные |
| `THIRD_PARTY_LICENSES.md` | нотисы сторонних компонентов (dsh/Cordis MIT, транзитивные зависимости) |

Инструменты работают напрямую с QA-хранилищем
`~/Library/Application Support/golos-meet-qa-b2c0b2c1c6e2413cba82e061cdb9cd97`
(только чтение; рабочее хранилище пользователя не затрагивается):

- **search_meetings** — FTS5-запрос по `knowledge_fts` (join на `embedding_chunks`),
  возврат цитат, таймкодов (`startSeconds`/`endSeconds` из `location`), id встречи
  и заголовка из `meta.json`. Фильтры `since`/`until` (YYYY-MM-DD), шумовые
  пустые сегменты (<5 символов, P3 из #93) отфильтрованы; стратегия AND-запрос
  с fallback на OR и ранжированием по числу совпавших слов.
- **summarize_meeting** — читает `meetings/<id>/transcript.json`, сжимает моделью
  (прямой REST-вызов OpenRouter, модель `deepseek/deepseek-v4.1-flash`).
  Перед облачным вызовом проверяет **egress-границу** (#94, принцип
  «согласие на облако — per-project» из PRODUCT_VISION §3.2): политику
  проектов встречи читает из того же knowledge.sqlite (READ-ONLY,
  `projects.cloud_policy` + `meeting_projects`; значения совпадают с
  `ProjectCloudPolicy` приложения). Вызов модели происходит только если
  **каждый** проект встречи имеет `allowSelectedContext`; `localOnly`,
  `askEveryTime`, отсутствие привязки встречи к проекту, отсутствие таблиц
  политики или недоступное хранилище — честный инструмент-результат
  «отправка запрещена политикой проекта» без вызова модели (fail closed).
  Схема политики в реальном QA-архиве проверена (2026-11-14): таблицы
  существуют, значения — `localOnly`/`askEveryTime`/`allowSelectedContext`.
- **search_meetings** — только локальный FTS5-запрос; облачного egress нет,
  гейт его не касается.

## Секреты и язык ответа

Ключ OpenRouter живёт в QA-Keychain
(`golos-meet.qa.b2c0b2c1c6e2413cba82e061cdb9cd97` / `openrouter-api-key`) и
передаётся **только** через переменную окружения `OPENROUTER_API_KEY` процесса
dsh (`run-web.sh` достаёт его `security find-generic-password -w` в момент
запуска). Ключ не хранится в файлах, логах и конфигах: `dsh-patch.yml` содержит
только имя переменной (`apiKeyEnv: OPENROUTER_API_KEY`).

Язык ответа (#103): персона `system-prompt.personaPrefix` в `dsh-patch.yml`
требует отвечать только по-русски и начинать сразу с содержимого, без
английских мета-фраз («I have enough grounded material…»); цитаты — дословно
с таймкодами. Второй слой страховки — фильтр `stripLeadingPreamble` в
`DshAgentRuntime.swift` (приложение) обрезает ведущую ASCII-преамбулу до
первого заголовка/кириллического символа, если она короче 200 символов.
Оба слоя проверены mock-e2e и Swift-тестами.

## Контракт профиля: никаких встроенных инструментов (#119)

Профиль `golos` создан из web-шаблона dsh, а в web-профиле модельные
инструменты составляются **из выбранного агентного пресета** (по умолчанию
`standard`): shipped-пресеты заново монтируют `tool-fs` (read/write/edit),
`tool-fs-search` (glob/grep), `tool-bash`, `tool-jobs`, `tool-web`,
`skill-filesystem` + `tool-skill`, subagent-делегирование, todo/goal/plan и
прочее — уже внутри каждой сессии. Именно это вызвало инцидент #119: на живой
вопрос агент пошёл glob-ом по домашним папкам, dsh вызвал файловые
инструменты, macOS поднял TCC-диалоги (Загрузки/Музыка/документы), прогон
завис.

Контракт спайка: **единственные модельные инструменты в профиле —
`search_meetings` и `summarize_meeting` из плагина golos-qa.** Он
обеспечивается в `dsh-patch.yml` двумя слоями:

1. **Host-плоскость.** Отключены (`- id: <service>` + `disabled: true`, паттерн
   как у `otel`) все строки-поставщики инструментов dsh-base: `tool-fs`,
   `tool-fs-search`, `tool-bash`, `tool-pwsh`, `tool-jobs`, `tool-web`,
   `skill-filesystem`, `tool-skill`, `tool-subagent*`, `workflow-ptc`,
   `tool-workflow`, `tool-todo`, `tool-goal`, `command-goal`, `plan-mode`,
   `tool-working-directory`, `mcp-resources`, `tool-plugin-manager`. Для web
   это повтор отключений самого web-бандла (контракт самодостаточен), для
   headless-профиля (только dsh-base, используется e2e и ночными прогонами) —
   реальное отключение, поэтому тот же список зеркалится в
   `test/dsh-patch.mock.yml`.
2. **Пресеты.** Все четыре shipped-пресета (`standard`, `ptc`, `minimal`,
   `cordis`) переопределены целиком (патч заменяет `config` строки, поэтому
   каждый переопределён декларацией с тем же `id`/`order` и списком плагинов
   «только инфраструктура»: `time-context` + группа компакции). Плагин
   `persona` из пресетов убран — русская персона живёт в `system-prompt`
   host-строке. Любой выбор пресета в web UI даёт одну и ту же безопасную
   композицию.

Проверки контракта:

- `test/profile-contract.sh` — собирает дерево профиля
  (`dsh golos --patch ./dsh-patch.yml --dump-config`, без запуска сервера) и
  ассертит: 20 строк инструментов `disabled: true`, в пресетах нет ни одного
  `dsh-tool-*`/скилла/персоны, строка `golos-qa` на месте, «живых»
  tool-подобных строк кроме реестра `tools` и нативного исполнителя нет.
- Mock-e2e (`test/e2e-mock.sh`) с #119 дополнительно падает, если в каталоге
  инструментов запроса к модели есть хоть что-то кроме `search_meetings`/
  `summarize_meeting` (`non-golos-tools=none` в логе mock-сервера).
- Живой прогон (2026-11-14, реальный ключ из QA-Keychain через env): вопрос
  «какие инструменты у тебя есть?» — модель перечисляет только
  `search_meetings` и `summarize_meeting`; провокация «посмотри файлы в
  Загрузках» — честный отказ «нет доступа к файловой системе»; `log show` по
  окнам прогонов — ни одного события TCC/SecurityAgent от процессов dsh
  (единственный pending при старте — отключённая телеметрия
  `session-telemetry-otel`, ожидающая выключенного `otel`).

Граница доступа агента — только QA-хранилище и каталог спайка (PRODUCT_VISION
§3.3, §3.6): любые новые инструменты добавляются через плагин golos-qa с
локальным/egress-гейтным доступом, никогда — включением встроенных
инструментов dsh.

## Запуск

```sh
cd research/dsh-spike-94
npm install          # ставит @deepseek-ai/dsh@0.2.2-rc.1
./run-web.sh         # поднимет http://127.0.0.1:3080 (токен печатается в stdout)
```

Первый запуск создаёт профиль `golos` (копия поставляемого web-профиля) в
локальном `.dsh-home/` (вне git). Открыть напечатанный URL
`http://127.0.0.1:3080/?token=…` в браузере и задать вопрос — агент увидит
инструменты `search_meetings` и `summarize_meeting`.

⚠️ Первый доступ к ключу через `security` вызывает диалог macOS: нужно ввести
пароль связки ключей «Вход» и нажать «Разрешить» (или «Разрешать всегда» —
тогда ночные запуски больше не спросят). Без этого шага `security -w` висит.

## Проверки

- **e2e без ключа (mock):** `test/e2e-mock.sh` — поднимает локальный mock-LLM
  (отдельный экземпляр на сценарий) и гоняет dsh headless в трёх случаях:
  - `PASS: search_meetings` — реальные цитаты и таймкоды архива дошли до модели;
  - `PASS: summarize_meeting` — встреча, привязанная к проекту с
    `allowSelectedContext`: плагин вызывает модель (тот же REST-путь, что и
    OpenRouter), сводка дошла до агента;
  - `PASS: summarize_denied` — встреча без привязки к проекту: egress-гейт
    вернул честный отказ «отправка запрещена политикой проекта», модель
    не вызывалась.
  Во всех случаях mock дополнительно проверяет, что русская инструкция
  персона («Отвечай только на русском языке…», #103) входит в system prompt
  запроса, и что каталог инструментов запроса — только два golos-инструмента
  (#119). Полный цикл «профиль → плагин → tool-вызов → результат в модель →
  ответ» проверен этим способом.

- **Контракт профиля (без ключа):** `test/profile-contract.sh` — ассерты
  состава собранного дерева профиля, см. раздел «Контракт профиля» выше (#119).

  Замечание: до 2026-11-14 mock получал `MOCK_TOOL` из окружения dsh, а не
  своего, поэтому оба сценария гоняли только `search_meetings`; это
  исправлено (mock перезапускается на сценарий).
- **Маршрут OpenRouter:** с фиктивным ключом dsh доводит запрос до
  `https://openrouter.ai/api/v1` и получает их 401 на невалидный ключ — то есть
  резолв модели `deepseek/deepseek-v4.1-flash` и передача env-ключа работают.

## Почему `research/`, а не `tools/`

Это спайк-артефакт для решения «dsh vs форк» (issue #94, фаза 0), а не
продуктовый код: здесь нет сборки в приложение, а `.dsh-home`/`node_modules`
локальны. Продуктовые обёртки (`search_meetings` над гибридным поиском,
consent-слой) переедут в `tools/` по итогам решения — см. план ночного
спринта в #94.
