# Preview-пакет для общей проверки (#25)

Пакет собирает **коммит**, а не незакоммиченные файлы рабочего дерева. Он не
означает готовности этапов 1–4: индекс, поиск и память ещё разрабатываются.
После принятия всех функциональных PR в `codex/product-preview` пакет нужно
пересобрать на согласованном SHA и независимо проверить. `main` не меняется;
итоговый [PR #8](https://github.com/marcusaure1ius/golos-meet/pull/8) ждёт
общего ручного теста и отдельного решения пользователя.

## Сборка без запуска

На macOS с Xcode, Python 3, Rust/Cargo и средствами командной строки:

```sh
make preview-package PREVIEW_REF=<полный-проверенный-SHA> PREVIEW_OUTPUT=/private/tmp/golos-preview
```

`PREVIEW_REF=HEAD` и `.build/preview` — значения по умолчанию. Для передачи
используйте SHA из независимого ревью. Скрипт сам не удостоверяет одобрение PR.
Исходники извлекаются через `git archive` в новый каталог; там же создаются
отдельные `DerivedData`, `RustTarget`, логи обеих сборок, каталог пакета и ZIP. Существующие
каталоги сборки не очищаются и не используются повторно. SwiftPM может получить
публичные зависимости; версии закреплены в `Package.resolved` и `asr/Cargo.lock`. Это не загрузка
весов и не вызов модели. Нужны место на диске и время на холодную сборку.

В ZIP входят только построенный `Golos Meet.app`, `manifest.json`, инвентарь
bundle и эта инструкция. Manifest содержит полный source SHA, tree, SHA-256
упаковщика/Package.resolved, версии зависимостей, Xcode и Rust, конфигурацию, Cargo.lock и результаты
статической проверки runtime и CLI smoke sidecar. Рядом с ZIP находится `package.sha256`.

Проверяются ID `com.golos.golos-meet`, Mach-O/архитектуры, embedded и связанный
ONNX Runtime, разрешение несистемных dylib-зависимостей внутри bundle,
отсутствие внешних symlink и файлов моделей/аудио/документов. Target `golos-meet`
и модуль `golos_meet` сохраняются. App не запускается. Упакованный ASR-sidecar запускается только с `--version`
и `--help`, которые выходят до Session/аудио. Проверка загрузки настоящей модели
и качества поиска в эту команду не входит.

Xcode создаёт локальную Debug-сборку без сертификата; после добавления sidecar
отдельная копия bundle подписывается ad-hoc (включая вложенный код) и проходит
`codesign --verify --deep --strict`. Notarization не выполняется. Она не
устанавливается в Applications и не заменяет работающий экземпляр. Стандартная регистрация временной build-app
в LaunchServices снимается через `lsregister -u` только для созданного пути;
установленные приложения и регистрации по bundle ID не удаляются. Скрипт не
обращается к Keychain или Application Support и не копирует оттуда данные,
модели либо бинарники. Логи, source и DerivedData остаются вне ZIP.

**ASR-sidecar:** `cargo build --release --locked --jobs 2` собирает binary из того же
снимка SHA в отдельный `RustTarget`, затем он включается в `Contents/Resources/golos-asr`.
Это существующий путь AppPaths; Swift, Rust source и pbxproj не меняются.
Зависимости Rust проверяются отдельно от Swift ONNX: текущий locked build
содержит статически связанные ORT/Whisper и только системные dylib. Если новая
сборка потребует несистемную dylib, упаковка завершится ошибкой с её именем,
пока для неё не будет добавлен явный путь упаковки. Системный или случайный
внешний binary не подставляется. Manifest содержит build command, Cargo.lock hash,
исходный SHA-256 binary, версии Rust/Cargo и результат CLI smoke уже упакованного
и подписанного sidecar. Это доказывает CLI-загрузку, а не транскрибацию.

Моделей в пакете нет. Веса E5 устанавливаются только явным выбором пользователя
в настройках. Установка весов ASR — отдельное ограничение; см. `asr/BUNDLING.md`
в репозитории. Без явно подготовленной модели живой ASR не объявляется проверенным.

## Безопасная библиотека перед будущим запуском

Не запускайте обычный app в рабочем аккаунте ради проверки пустой библиотеки:
он использует рабочие AppPaths и стартует восстановление/детектор. Переименование
bundle/каталога приложения или другая папка output не изолируют хранилище и Keychain.
`GOLOS_MEET_TEST_MODE=1` изолирует тесты, но выключает рабочий UI и запись;
полную ручную проверку он не заменяет. Подмена HOME не является поддерживаемым
способом изоляции Foundation/Keychain/TCC.

Существующего полноценного режима временной библиотеки нет. С координатором зафиксированы варианты: отдельно выбранная учётная запись macOS для проверки либо
отдельно согласованная задача явного временного хранилища. До выбора варианта
и данных пакет только собирается и инспектируется. Нового режима здесь нет.
Для изолированного аккаунта пользователь отдельно выбирает синтетические или
одноразовые файлы; рабочая библиотека, ключи и модели автоматически не переносятся.

## План общей ручной проверки после завершения feature PR

В отчёте каждого сценария фиксируются SHA из manifest, macOS/устройство,
выбранные данные, действие, наблюдаемый результат и ограничения. Статусы:
«не реализовано», «не проверено», «прошло», «ошибка». Успех unit/synthetic
теста не заменяет живую проверку. Пока нужный UI/контракт не принят, сценарий
остаётся «не реализовано», а не считается успешным.

| Область | Что дают unit/synthetic проверки | Что отдельно проверить вручную |
|---|---|---|
| Запись и индикация | Fake tracks, задержки/ошибки/отмена, финализация временных WAV, сохранность короткой ручной записи | После явного выбора тестового звонка: TCC микрофона/экрана, готовность двух дорожек, старт/стоп и длительность; прослушать обе дорожки, проверить качество, тайминги и sync. Mute/тишина, сон/пробуждение, переподключение, смена устройства/телефон; запись не теряется. Native filter должен захватывать Толк, а не сторонний звук. Это пока live-ограничения. |
| Толк | Подменённый транспорт PAT и ошибки доступа | Пользователь при необходимости вводит PAT только в приложении. Проверка профиля не подтверждает API-режим участия. Определение комнаты/сервер вебхуков отложены; текущий режим — эвристика аудио/окон. API-вход/выход не отмечать проверенным. Календаря нет. |
| Проекты / M:N | SQLite-контракты, ограничения и миграции на временных БД | В явно выбранной тестовой библиотеке создать два проекта; один источник связан с обоими, ручное переназначение не перемещает аудио и не теряет связи. |
| Импорт, версии и очередь | Синтетические DOCX/PDF/OCR, отмена, дедупликация, версии | Выбрать тестовые файлы, повторить импорт/изменить версию, отменить и повторить, проверить прогресс/ошибки и оригиналы. Индексация не мешает записи и ASR; удаление только одноразовых данных. |
| Локальные модель, поиск и источники | Токены/векторы на синтетике; проверка установщика; будущие тесты индекса | Явно выбрать установку E5, проверить ошибку/отмену/повтор; русские запросы по тестовым документам/встречам, переход к странице/таймкоду, новая версия и переиндексация. В этом пакете веса не включены; качество не доказано сборкой. |
| Облачные разрешения и память | Stub транспорта: запреты проектов, общие источники, ссылки и будущие контракты памяти | До сетевых действий пользователь выбирает проект и разрешает передачу выбранных данных. Проверить запрет по умолчанию, всех владельцев общего источника, отмену разрешения, ответы с проверяемыми ссылками, недостаток данных, историю/конфликты/ручные исправления. Живой OpenRouter — отдельный сценарий; секреты не в отчёте. |

Constance (#6) и UI-редизайн (#18/#19) отложены. Ни успешная сборка, ни
пробная упаковка принятого preview не закрывают всю ручную приёмку продукта.

## Проверки упаковщика

```sh
python3 -B research/preview-package/test_package_preview.py
```

Три guard-регрессии используют только временные синтетические файлы: запрет
упаковки моделей/аудио/документов, отказ внешним/битым symlink и неизвестному
source ref до создания сборки. Полная проверка команды выполняет обе сборки,
инспекцию bundle, подпись и CLI smoke. Перед передачей ZIP также проверяются
распаковка в другой путь, совпадение inventory/hash и повторный CLI smoke;
запуск приложения и живые сценарии из плана остаются отдельным этапом.
