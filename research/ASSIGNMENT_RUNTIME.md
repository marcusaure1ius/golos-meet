## Состав и поведение

Schema v6 добавляет `assignment_work`: input fingerprint, durable lease generation, state и понятное сообщение. Новые таблица/индекс создаются под существующим BEGIN IMMEDIATE. Решения/manual Inbox/M:N/документы/версии/векторы не переписываются; timeout/retry SQLite не менялись. Существующие synthetic downgrade fixtures очищают и v6-объект перед проверкой старых миграций.

`MeetingAssignmentWorker` — отдельный последовательный utility worker, без encoder/ASR/recording/облачного клиента. Он читает уже готовые векторы и не запускает индексирование источника по кнопке повтора распределения. Round-robin cursor даёт следующим встречам пройти после ошибки предыдущей. Отмена, retry и crash recovery сохраняются в SQLite. Restart восстанавливает running как pending; canceled остаётся canceled до явного retry. Ручные решения имеют приоритет, включая пустой выбор.

Стабильный input включает активную модель/размерность/epoch, проекты, trusted context (документы и manual-встречи), каталог/job generation/state, владельцев контекста и файловые identities. Auto/proposal-встречи не становятся контекстом; их публикация не меняет собственный input и не создаёт цикл пересборки. Идентичный пересчёт не меняет lease/решение. Отсутствующий/ошибочный trusted context не исчезает из сравнения.

При изменившемся input прежние auto-связи **снимаются до пересчёта**, историческое объяснение остаётся в decision payload, но не показывается как актуальное. Pending/running/waiting/error/cancelled не имеют активной auto-связи. Manual-связи не снимаются. Повтор того же результата умеет восстановить снятые связи, а не ошибочно вернуть unchanged при пустой таблице владельцев.

Production `KnowledgeAssignments` запускается в AppDelegate рядом с индексатором и живёт независимо от открытого окна/вкладки. Получает stream индексатора и metadata-сигналы импорта/расшифровки/модели/ручных проектов, плюс сверяет библиотеку раз в 30 секунд. Новое `.projects` событие не переиндексирует источник. Перезагрузка ProjectLibrary coalesced и выполняется после незавершённого ручного сохранения. Неизменившиеся снимки не вызывают постоянную перезагрузку проектов.

Работающий runtime индексатора — явное условие production-очереди: одних оставшихся в SQLite векторов после недоступности модели недостаточно, чтобы показывать current. Потеря runtime инвалидирует lease и снимает auto-связи; восстановление меняет input и запускает пересчёт. Сохранённая прежняя рабочая модель при неудачной замене по принятому контракту индексатора продолжает считаться работающей.

Пределы engine не менялись: 200 проектов, 2000 окон, 100 000 операций сравнения/владельцев. Worker ставит deadline 10 секунд: durable state/lease инвалидируется, затем запрашивается cooperative cancellation. Новый расчёт не перекрывает фактически ещё не завершившийся предыдущий. Swift не убивает принудительно некооперативную нативную операцию; source reader проверяет отмену между ограниченными чтениями, engine — в циклах. Отказ записи состояния виден, осиротевший running восстанавливается при следующей сверке. Ошибки не вызывают непрерывного автоматического retry; повреждённый текст/отмену индексирования нужно исправить отдельно.

## Стартовая гонка и ограниченный повтор

В реальном UI выявлено: другие, не участвующие в сравнении встречи могут закончить индексирование между prepare и commit. Полный принятый checkpoint отвергает старый план; прежний runtime оставлял его в generic error, хотя его собственный input уже не менялся. Ручной retry проходил. Это исправлено без ослабления CAS engine и без переиндексации источника.

Superseded/stale-план возвращается в pending с новым durable lease. Локальная метка request не позволяет повторять одну попытку без нового внешнего события. Событие индексатора, пришедшее во время старого расчёта, разрешает одну новую попытку сразу; иначе — следующее событие/периодическая сверка/явный retry. Непрерывного цикла нет. Cancelled/manual/реальная ошибка текста от этого не сбрасываются. Содержательная gated регрессия завершает индексирование чужой встречи при удержанном плане и подтверждает автоматический current обеих встреч без кнопки retry.

## Открытие сохранённого основания и UI

`MeetingAssignmentEvidenceReader` требует current work, неизменный decision, модель/размерность/epoch и актуальный input. Проверяет обе стороны по принятому search snapshot контракту: chunk и ревизия, file stamp, fingerprint/SHA-256, принадлежность контекста проекту. У документов source revision — UUID версии, chunk revision — content hash; они различаются намеренно. Финальная транзакция вновь сверяет checkpoint/work/decision. Viewer получает проверенные Data/chunks и время снимка, URL повторно не читает; аудио не запускается.

В деталях встречи показаны manual / auto / proposal / pending / running / waiting / error / cancelled, отмена и повтор. Автоматический M:N не требует подтверждения. Предложение объясняет отсутствие однозначного имени или конкуренцию, показывает фрагмент, cosine/преимущество и переходы к реплике/контексту. Значения названы эвристикой, не вероятностью. Ручной выбор открывает существующий полный M:N редактор. Новая тема открывает редактируемую форму создания; после явного создания назначение становится manual. Проект сам не создаётся.

Сеть/Keychain/рабочие записи не нужны. Test host блокирует ProductionAssignments до AppPaths/сервиса; это дополнительно проверено в TestHostIsolationTests. Main target/module/bundle id не переименовывались.

Финальный make check: **309 тестов / 373 параметризованных запуска / 0 ошибок / 2 gated skips**. Настоящий ASR E2E исключён. Лог `/tmp/golos14-runtime-final-check.log`, xcresult `Test-golos-meet-2026.10.31_22-13-35-+0300.xcresult`. Существующее QoS warning LocalDocumentExtractorTests сохраняется; новых warnings в изменённых assignment/ProjectLibrary файлах не обнаружено. Rust не менялся.

Новые lifecycle-тесты используют явный tiny encoder: background bridge без экрана, current→stale-снятие→ready-восстановление, unchanged без churn, cancel/restart и late publisher, stop/start/manual Inbox, fairness после ошибки, missing runtime/recovery, deadline против некооперативного detached publisher, source/model/file ABA/reindex/scope при открытии, bounded startup retry после чужого ready, отсутствие reindex от ручного выбора. Это проверки жизненного цикла, не оценка семантики.

Native CLI `--runtime` использует настоящую public pinned E5 и SQLite. Индексирует synthetic документы/расшифровки, запускает serial worker, проверяет persisted decisions, открывает обе стороны evidence, делает reindex → снятие связи/отказ старого evidence → восстановление ready, unchanged и manual Inbox после новой connection/restart. Native CLI вызывает worker явно: настоящий AppDelegate/запись не запускались; production stream/notification bridge проверен отдельно в Swift-тесте и isolated UI. Флаги `production_wiring:false` / `serial_worker:true` в JSON отражают эту границу.

В ходе разработки исправлены: смешение UUID версии документа с hash фрагмента в evidence guard; лишняя перезагрузка ProjectLibrary во время ручного выбора; стартовая CAS-гонка выше. Ранние прогоны до этих исправлений не выдаются за passed. Swift frontend также аварийно завершил диагностику некорректного обращения к error-state в catch; исправлено обращение self.error, обходных compiler flags нет.

Fixture-кнопки повреждают только управляемую synthetic копию или удерживают расчёт; это не продуктовые кнопки и не измерение latency.

## Покрытие и оставшийся #45

`runtime-evaluation.json`: прежняя policy evaluation 12 сценариев → **4 TP / 0 FP / 0 ожидаемых пропусков** по связям, включая M:N. Это малый authored corpus с ограниченной разметкой «auto при выполнении exact-name policy», а не доказательство полноты исходной цели распределения по смыслу.

Отдельный новый `runtime-name-controls.json` размечен по **желаемой принадлежности по содержимому**, не по ограничениям engine: 8 сценариев → **1 TP / 0 FP / 6 пропущенных связей**. Буквальное длинное имя проходит; без имени, со склонением «для Янтаря», коротким «ИИ» и M:N из таких реплик связи не назначены автоматически. Они остаются предложениями. Итоговые наборы не использовались для изменения порогов; engine v2/0,90/0,04 сохранён. SHA корпусов, actual/expected и raw scores находятся в JSON; TP/FP/FN и SHA дополнительно пересчитаны Python.

Контроль — подтверждённый дефицит покрытия, а не успешное завершение #14. Следующий конкретный шаг уже оформлен координатором в #45: самостоятельный семантический маршрут без обязательного полного имени, с доказательствами из доверенных источников/сравнением конкурентов и отдельными calibration/regression/новой evaluation. Проверить короткие/склонённые/отсутствующие имена, переименование и отрицательные/неоднозначные контексты; сохранить manual/Inbox/CAS/all-owner scope/лимиты и не обучаться на auto. Не выбирать пороги на этих итоговых control примерах. Начало #45 — только после независимого принятия этого runtime PR, новая ветка от свежего preview.

В финальном CLI-прогоне 12-case набора: cold runtime+индекс 16 источников 1.291 с, начальный drain worker 0.117 с; медиана последующего prepare+unchanged commit+открытий evidence 14.70 мс, peak CLI RSS 1849311232 байт. Для 8 controls: индекс 1.132 с, drain 0.065 с. Это разные интервалы; медиана **не** latency первого автоматического назначения и не сопоставима напрямую с прежними 7,91 мс prepare+commit. M4 Pro/24 ГБ/macOS 27.0.1, Debug/Onone; disk cache не сбрасывался. Большой архив, app RSS/UI latency/живой звонок не измерены.

FS и SQLite не атомарны, внешняя запись после последней проверки остаётся возможной. Периодическая сверка имеет интервал 30 секунд; открытие основания всегда проверяется заново. Рабочие 2–3 проекта/аудио не читались, новые модели не скачивались, облако/секреты/календарь не использовались. PR — Refs #14; дальнейшее независимое ревью актуального SHA и приёмка только координатором в preview.
