# Исследование рабочей области Golos Meet

31 октября 2026 · первая часть #18 · варианты ещё не согласованы.

## Вывод

Для первого обсуждения достаточно двух архитектур: A — проект/материал в центре и контекстный чат справа; B — диалог в центре и материалы справа. Обе сохраняют дерево проектов, источник рядом с ответом и независимый статус записи. Предварительно рекомендую A для Golos Meet: обзор и проверка исходного материала доступны до формулирования запроса. Это вывод из сценариев, а не установленное предпочтение пользователя. B сильнее, если основная работа начинается с вопроса и синтеза нескольких материалов.

## Что прочитано и что из этого следует

Использованы только публичные первичные источники. Приложение Codex через CUA не открывалось; его рабочие чаты и файлы не обследовались. Ниже «наблюдение» означает описанное в документации поведение, «применение» — наше предложение для Golos Meet, а не утверждение о сходстве продуктов во всех деталях.

## Apple и техническая применимость

| Проверка | Факт / решение |
|---|---|
| [HIG Materials](https://developer.apple.com/design/human-interface-guidelines/materials) | Liquid Glass образует функциональный слой навигации и контролов; HIG предостерегает от переноса его в содержимое. Поэтому PDF, транскрипт, ответ и результаты поиска остаются непрозрачными. Для текстовой навигации — regular, не clear. |
| [HIG Sidebars](https://developer.apple.com/design/human-interface-guidelines/sidebars) | Сворачиваемая иерархия, короткие подписи, знакомые символы, возможность скрыть sidebar. Критичные действия не прячем внизу дерева. Наш статус записи закреплён сверху и доступен в menu bar. |
| [SwiftUI glassEffect](https://developer.apple.com/documentation/swiftui/view/glasseffect(_:in:)), [NSGlassEffectView](https://developer.apple.com/documentation/appkit/nsglasseffectview) | Оба доступны с macOS 26.0. В репозитории deployment target 14.4. Сохранение 14.4 возможно через availability-ветвление и стандартный material/opaque fallback. Повышение ОС не требуется для архитектуры; решения о его повышении нет. |
| [NavigationSplitView](https://developer.apple.com/documentation/swiftui/navigationsplitview), [AppKit WWDC25](https://developer.apple.com/videos/play/wwdc2025/310/) | NavigationSplitView доступен с macOS 13. Для сложного управления ширинами, фокусом и редактором можно оценить NSSplitViewController/NSHostingView. Выбор между ними должен опираться на выбранную композицию, а не на необходимость рисовать стекло вручную. |
| [Applying Liquid Glass](https://developer.apple.com/documentation/swiftui/applying-liquid-glass-to-custom-views) | Несколько близких glass-элементов группируются контейнером; большое число эффектов ухудшает rendering. В плане — минимум пользовательских эффектов и отдельное измерение scroll/resize, без blur на каждой строке. |
| [HIG Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility) | Системные цвета, проверка обеих тем, keyboard-only и VoiceOver; Reduce Motion должен уменьшать движение. В brief заданы фокус/объявления/opaque режим. Реальная accessibility-проверка этих контрактов ещё не выполнена. |

Проверено локально: Xcode 27.1 (`27A9275`), macOS SDK 27.0; `MACOSX_DEPLOYMENT_TARGET = 14.4` в проекте. Изолированный host скомпилирован `-target arm64-apple-macos14.4` с `#available(macOS 26.0, *)` для нового API. Это проверяет совместимость исходника с deployment target, **не запуск на macOS 14.4**. Первичные Markdown-страницы Apple прочитаны напрямую: web reader не поддержал их `text/markdown`.

## Сопоставление на одном сценарии

| Работа | A — проект/материал | B — чат/материалы |
|---|---|---|
| Вернуться утром | Обзор сразу показывает изменения, материалы и открытые вопросы. | Открыт диалог; обзор нужно выбрать в панели. |
| Проверить ответ | Ссылка меняет центральный материал, чат остаётся справа. | Ссылка меняет правую панель, вопрос остаётся в центре. |
| Читать длинный PDF | Больше места источнику уже по умолчанию. | Нужно расширить материал/временно скрыть диалог. |
| Синтезировать два источника | Небольшой чат рядом, фокус на доказательствах. | Больше места сравнению и follow-up вопросам. |
| Работать с задачей | Задачный список/редактор в центре, источник связан ссылкой. | Редактор в правой панели, обсуждение остаётся рядом. |
| Встреча в процессе | Статус сверху; можно открыть память без закрытия записи. | Статус сверху; разговор с проектом остаётся основной работой. Живой ASR не предполагается. |

## Результат и ограничения первой части

Создан 21 PNG из самостоятельного SwiftUI/AppKit render host: по 7 общих сценариев A/B, два fullscreen dark, два reduced, состояния, запись/menu bar, настройки. Полный указатель — [README](README.md), поведенческий контракт и вопросы — [BRIEF](BRIEF.md). Продуктовая истина — корневой `PRODUCT.md`.

Host имеет уникальный bundle `com.golos.research.ui18.synthetic`, не импортирует Golos, не имеет production AppDelegate и не создаёт фоновые сервисы. Данные зашиты строками; рабочая библиотека, секреты, микрофон, восстановление, ASR, модели, сеть и Constance не используются. Окна не выводятся на рабочий стол; рендеры получены через NSHostingView/cacheDisplay. Исходники и повторяемый скрипт включены.

PNG — **концептуальные нативные рендеры**, не работающая интеграция и не снятый production-экран. Нативные controls, SF и системные цвета настоящие, но offscreen snapshot не передаёт оптический glass корректно. Для экспортов glass-контрол имеет непрозрачную подложку; production-оптика должна проверяться на системном окне после выбора. Fullscreen здесь означает композицию viewport 1920×1080, а не испытанный системный переход/Spaces. Плеер, редактор задачи, отправка и системные разрешения не работают; кнопки обозначают будущие действия. Resize divider, сохранение фокуса, VoiceOver и responsiveness пока специфицированы, а не проверены на живом прототипе. Исследование не закрывает #18.

Следующий шаг после выбора: уточнить поведение панелей и задачи #6, собрать интерактивный synthetic host с настоящим split/focus/toolbar и macOS availability, проверить обе темы и accessibility на системном окне, получить согласование. Передача #19 возможна только после этого и независимого ревью конкретного SHA. Production UI, backend, deployment target и workflow-документы не менялись.
