# Хранилище векторов и актуальность источников

Часть #13 после принятого PR #24. Этот PR сохраняет настоящие векторы E5 и
проверяет протокол публикации на синтетических материалах. Автоматический запуск
индексирования из приложения, общий runtime service, очередь и UI состояния,
сравнение кандидатов остаются следующими обязательными изменениями. Поиск и
автораспределение из #14 здесь не реализуются. Модель не скачивается автоматически.

## Идентичность и хранение

Schema v3 той же `knowledge.sqlite` добавляет реестр моделей/размерностей,
активную модель, источники, снимки фрагментов, задания и float32 BLOB-векторы.
Формат BLOB — little endian, четыре байта на компонент. При чтении проверяются
размер, конечные значения и единичная норма. Повреждение не выдаётся за пустой
успешный результат поиска.

Документ определяется UUID, его текущая ревизия — UUID сохранённой версии.
Фрагмент также сохраняет hash содержимого и исходную страницу/абзац. Переключение
версии документа, обновление источника индекса, инвалидирование прежних векторов
и новое поколение задания коммитятся в одной транзакции импорта. Оригиналы и
исторические версии не удаляются. Источники, импортированные до v3, регистрируются
явным `synchronizeEmbeddingDocuments()`; запуск фоновой очереди добавляется отдельно.

Встреча определяется постоянным ID папки, её ревизия — SHA-256 байтов
`transcript.json`. Mtime не используется. Для chunk source UUID берётся устойчивый
namespace-хеш ID встречи. Читается только расшифровка; аудио и insights не открываются.
Таймкоды сохраняются. Один источник имеет один набор векторов независимо от числа
проектов-владельцев; назначение проектов остаётся в исходных таблицах связей.

У каждого задания есть случайное поколение. Оно меняется при новой ревизии,
смене модели, отмене/повторе, восстановлении прерванной обработки и явной
переиндексации. Каждый захват задания дополнительно получает уникальный attempt.
Совпадения текущего ID версии или модели недостаточно: после A→B→A прежние
generation/attempt уже недействительны. Одна модель не может повторно объявить
другую размерность под тем же ID, даже после переключения на промежуточную модель.

Публикация проверяет активную модель, текущую ревизию документа, поколение,
attempt и состояние running. Прогресс и ошибки проходят ту же проверку.
Публикуется полный набор фрагментов и окон: начало с нуля, отсутствие разрывов,
продвижение каждого окна и покрытие до последнего токена. Общее число токенов
фрагмента сохраняется для проверки утраты хвостового окна после перезапуска.
Ошибка SQL, неполный набор или отмена откатывают всю публикацию. Чтение доступно
только для состояния ready и активной модели.

## Контракт файловой расшифровки и будущей очереди

SQLite не образует общей транзакции с внешним файлом `transcript.json`.
`MeetingEmbeddingSnapshotReader.synchronize` наблюдает текущую ревизию каталога,
читает новый снимок и регистрирует его через compare-and-swap. Задержавшийся
скан не может отменить уже зарегистрированный новый снимок. Повреждённая или
удалённая расшифровка инвалидирует прежний производный индекс с тем же CAS;
оригинальный файл не меняется.

Будущая очередь обязана повторно синхронизировать встречу перед публикацией;
обработчики изменений файлов и слой поиска также должны обновлять наблюдаемый
снимок. Эти production hooks ещё не подключены, поэтому текущая часть не обещает
немедленно обнаруживать произвольную внешнюю запись файла. После регистрации
нового fingerprint старый результат не принимается, включая возврат к прежним
байтам. Миграция/claim/publish синхронизированы SQLite-транзакциями, но
`recoverEmbeddingJobs()` вызывается только на старте при отсутствии живой очереди.
Захват возвращает следующий доступный source key; политику планирования очереди
и реакцию на отсутствие весов добавляет следующая часть.

## Проверки

Обычный `make check` использует маленькие явно синтетические векторы только для
проверок SQLite/lifecycle, не выдавая их за семантическую модель. Регрессии покрывают:

- настоящий импорт документа, shared ownership, идемпотентную регистрацию и reopen;
- source/model A→B→A, отсутствие смешивания размерностей;
- эксклюзивный claim двумя соединениями, поздние progress/fail/commit после
  cancel/retry/restart и повторную публикацию завершённого attempt;
- удаление источника с cascade и восстановление того же ID/ревизии;
- пропущенные фрагменты, разрыв окон, другую модель, отказ SQL посреди вставки,
  утрату хвостового окна и повреждённый BLOB;
- откат версии документа вместе с источником индекса при ошибке инвалидирования;
- миграцию существующих документов и rollback незавершённой DDL-миграции;
- настоящие переписывания transcript A→B→A при одинаковом mtime, таймкоды,
  устаревший CAS, повреждение, удаление и символические ссылки.

Настоящий E5 запускается только с явно заданным комплектом весов:

```sh
TEST_RUNNER_GOLOS_MEET_E5_FOLDER=/path/to/pinned-e5-small make check
```

`EmbeddingIndexNativeTests` действительно извлекает синтетические TXT/PDF,
читает расшифровку, считает E5-окна, пишет float32 BLOB и читает их через новое
соединение. Проверены model/source/revision/window identity, страницы, таймкоды,
покрытие длинного Unicode-текста и близость сохранённых/вычисленных векторов.
Расчёт удерживается после первого настоящего фрагмента, затем исходный файл
меняется A→B→A, и поздняя публикация отклоняется. Это проверено и для документа,
и для расшифровки. Аудио не создаётся и не читается.

Итоговый полный прогон с настоящим E5: 242 теста, 275 запусков с параметрами,
0 ошибок, 2 optional render skips; настоящий ASR E2E исключён. Сохраняются
предсуществующие предупреждения сборки и QoS warning извлечения текста.

Отдельный CLI компилирует тот же production core без приложения, AppPaths,
Keychain, UI и ASR. Python только вызывает компилятор:

```sh
make build
python3 research/build_native_embedding_probe.py --index
sandbox-exec -p '(version 1)(allow default)(deny network*)' \
  /tmp/golos-native-embedding-index-probe /path/to/pinned-e5-small /tmp/index-offline.json
```

Проверено 30 октября 2026: два синтетических источника, шесть настоящих окон E5,
384 измерения, повторное чтение SQLite, сеть запрещена. Сводка идентичностей —
`native-index-offline-2026-10-30.json`. Это smoke-тест локальности/persistence,
не сравнение качества моделей и не доказательство готовности фоновой очереди.
