## Контракт

`KnowledgeQuestionService` получает явные store/search/roots/ChatCompleter/model. Он не подключён к production UI или AppDelegate, не читает Keychain и не запускает worker. Следующий отдельный PR добавит UI/runtime после независимого принятия сервиса.

1. `prepare(question:projectID:retrievalQuery:)` заменяет предыдущую сессию, выполняет принятый локальный поиск и возвращает неизменяемый preview. Вопрос до 4000 символов; retrieval использует прежний контракт 256 символов / 20 слов. Для длинного вопроса можно явно передать короткий retrievalQuery. Неизвестная область и пустые результаты — ошибки.
2. Из ранжированного результата выбираются до 12 фрагментов, суммарно до 16000 символов текста и заголовков. Preview содержит точный набор, исходные locations, ревизии фрагментов/источников, поколения source/model, владельцев, политики и число этих символов. Полный searchResponse остаётся локальным для объяснения отбора; в генератор передаются только hits выбранного preview. В payload также входят вопрос, имя проекта, locations и метаданные; textCharacterCount не выдаётся за размер всего HTTP JSON или число токенов.
3. `approve(request)` вызывается явным подтверждением этого preview, выдаёт непрозрачный токен и не сохраняет политику. `localOnly` не допускает отправку, `askEveryTime` требует разрешения каждого владельца, `allowSelectedContext` допускает выбранный контекст. Неизвестный владелец/нечитаемая политика запрещают отправку. Токен привязан к ID неизменяемого запроса в конкретном экземпляре сервиса; pending request и токен потребляются до первого await answer, в том числе при ошибке. Повтор — новый prepare и при необходимости новое согласие.
4. Файлы проверяются по принятому reader: hash/chunks и stamp (inode/birth/ctime/mtime/size), затем stamps ранних файлов проверяются повторно. В одной SQLite transaction проверяются выбранные chunks, ревизии/поколения источников и модели, состав владельцев и текущие политики. Существующий assignment_epoch ловит policy/owner ABA и пересоздание проекта; миграция не нужна. Он глобальный: даже постороннее изменение назначения может консервативно потребовать повторить вопрос.
5. После асинхронного retrieval, перед подтверждением, перед вызовом генератора и через `ChatCompleter.beforeSending` у транспорта контекст проверяется снова. OpenRouter вызывает gate перед каждой HTTP-попыткой, включая retry; исключение gate не попадает в retry catch, cancellation не проглатывается. Default guarded method предназначен для single-attempt адаптеров; новый retrying адаптер обязан переопределить его и проверять каждую попытку, как OpenRouter.
6. Перед возвратом ответа выполняется postflight. `cancel`/новый prepare (в том числе с другим проектом)/отмена Task/изменённый источник или политика не дают вернуть поздний ответ. UI обязан вызывать cancel/prepare при смене вопроса/проекта; готовая модель UI в этот PR не входит.
7. Генератор получает JSON с выбранными фрагментами и системным правилом считать их текст данными. Ответ проверяется структурно: JSON, непустой текст, недостаток оснований, действительные метки sources и inline-ссылки. Это не доказательство фактической истинности текста LLM. Каждая citation хранит source/chunk ID, обе ревизии, location и отдельные даты.
8. `openCitation` использует исходный hit и прежний search.open: заново проверяет freshness и возвращает проверенные bytes/chunks, а не изменяемый URL. При новой/недоступной версии — явная ошибка; уже возвращённый snapshot остаётся снимком старой версии. `sourceDate` пока неизвестна, если принятый search-контракт не дал подтверждённой даты; importedAt сохраняется отдельно и никогда не подставляется как дата источника/решения. Вопрос об отображении этих данных входит в следующий UI PR.

## Локальная граница

Последняя файловая проверка → SQLite snapshot/check → session/cancellation fence → передача транспорта. Файлы, SQLite, Swift actors и сервер не образуют общей атомарной транзакции. После границы нельзя отозвать уже отправленные байты. Retry проходит новый gate; late response — postflight. Нативные операции, игнорирующие cancellation, не обещаны как принудительно остановленные.

Транзитивное происхождение будущей памяти, история/worker #36/#37 и дизайн #19 сюда не включены. Пока в контекст попадают только исходники принятого локального search, не производные события будущего журнала. Новых весов, пользовательских записей, реальных документов, API/облака или production capture/ASR для проверок не использовано.
