## Подключение и хранение

`TalkCredential` получает необязательную UUID version, совместимую со старой JSON-записью Keychain. При первом явном сохранении legacy PAT создаётся версия; новый origin/действительно другой PAT получает новую UUID. Сохранение неизменного подключения сохраняет версию. Секрет по-прежнему в одном Keychain item вместе с origin, не в settings JSON/URL/логах/обратной подстановке UI.

`talk-meeting-settings.json` в AppPaths.appSupport атомарно хранит schemaVersion=1, origin, connectionVersion, нормализованные rooms и подтверждённую карточку (key/login/имя/email). Токена и его хэша там нет. При несовпадении origin/version прежние комнаты/подтверждение не используются. Смена draft origin/PAT сразу отвязывает модель, очищает карточку и отменяет поиск; старый файл не переносится на новую связь. Возврат/сохранение неизменного подключения может восстановить его ранее сохранённые настройки. Удаление PAT отвязывает модель и удаляет preferences; отказ удаления файла показывается, оставшаяся версия недействительна для нового подключения.

Настройки повторно валидируются при чтении. Ошибка чтения/записи видна, успешное сохранение не заявляется после отказа. Это не транзакция двух хранилищ: сначала атомарно сохраняется Keychain credential; несоответствие version не позволяет применить старую identity к новому PAT даже при оставшемся preferences-файле. Для test host AppPaths временный; тесты этой части используют отдельные memory stores/явные временные файлы.

## Комнаты

Редактируемые строки, добавление/удаление, ошибка каждой строки до сохранения. Переиспользуется TalkRoomConfiguration: lowercase ID/цифры либо URL того же HTTPS origin без query/fragment/credentials/encoded path; дедупликация/сортировка. Ограничения до 10 разных комнат и до 128 байт на ID локальные, не лимиты API. Пустой список можно сохранить для очистки настроек; runtime не включает observer без комнат. «Сохранить комнаты» фиксирует только комнаты и уже подтверждённый аккаунт.

## Поиск и подтверждение

По первичной PAT-спецификации [GET /api/Users](https://developer.kontur.ru/doc/talk.personal-access-token.api) поддерживает email-фильтр. Поиск произвольного login не обещается. Почта валидируется и передаётся единственным URLQueryItem email; `+` дополнительно кодируется `%2B` для form-style серверных декодеров. PAT только в X-Auth-Token, shared budget и redirect/ephemeral/error-контракт принятых клиентов сохраняются. Тела и URL-параметры не логируются.

Результат показывает имя/login/email. Нет автоматического выбора по имени, единственному результату или совпадению с profile. Только «Это мой аккаунт» фиксирует key карточки из актуального результата. Неизвестный/пустой/повторяющийся key отклоняется транспортом. Выбор подтверждает намерение пользователя наблюдать этот аккаунт, а не принадлежность PAT. Сохранение identity не коммитит несохранённые room drafts.

Состояния: idle, loading/отмена, пустой результат, одна/несколько карточек, безопасная ошибка, confirmed. Изменение email, origin/PAT, cancel/delete инвалидирует revision/Task; ответ игнорирующего отмену lookup не возвращает старые результаты/выбор. Сохранённое подтверждение того же подключения остаётся действительным при новом поиске; оно заменяется только новым явным подтверждением или отвязкой подключения. Повторное присваивание неизменного поля подключения не сбрасывает дочернюю модель (регрессия выявлена реальным SwiftUI host).

## Решение пользователя и последующая часть

Пользователь подтвердил поиск и выбор аккаунта, всегда входит muted и участвует только с этого Mac. В #41 автостарт определяется API presence выбранного userKey, без IsRunningInput и кнопки каждого звонка; muted join запускает, mute/тишина не завершают, unknown не равен выходу. Native capture/process readiness guard сохраняется для готовности захвата. API не доказывает устройство; использование одного Mac — явное продуктовое допущение пользователя. Старые варианты обязательной mic-активности/локального подтверждения каждого звонка отменены. В #40 само сохранение/поиск не запускают запись и не включают новый режим.
