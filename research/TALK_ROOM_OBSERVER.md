# Observer комнат через PAT — #38

Первая часть API-режима родителя #3. Не подключена к AppCoordinator/Recorder и не заменяет эвристический детектор. Не читает Keychain, не ищет окна, не запускает аудио, календарь или облачную обработку. Default transport observer отключён в test host; тесты явно подставляют transport.

## Конфигурация и идентичность

`TalkRoomConfiguration` принимает credential одного HTTPS origin, список идентификаторов/ссылок и явно подтверждённый в будущем UI `userKey`. Формат ключа комнаты взят из официальной PAT-спецификации: lowercase ASCII a–z и цифры. Пробелы вокруг ввода убираются; одинаковые комнаты сортируются/дедуплицируются. Для ссылок допустим только тот же origin, один путь комнаты с необязательным завершающим `/`, без credentials, query, fragment и percent-encoded пути. Host и стандартный HTTPS port канонизируются. Неверный элемент отклоняет весь список.

Локальные продуктовые ограничения этой части: 1–10 разных комнат, идентификатор до 128 байт. Они ограничивают длительность обхода; это не объявляется лимитом сервера. User key сравнивается точно, без изменения регистра и без сопоставления по имени, email или conference uniqueId. Аноним не подтверждает целевой аккаунт. Если зарегистрированный участник не имеет читаемого непустого key, весь ответ считается некорректным: он мог быть целевым пользователем. Источник user key не угадывается: см. исследование и открытый вопрос пользователя в TALK_API_PATH.md.

## Состояния и свежесть

Один последовательный цикл обходит текущие комнаты без кэша. После полного успешного цикла возвращается `present(rooms:)` (все комнаты с целевым аккаунтом) либо `absent`. Присутствие сразу в нескольких комнатах — одно состояние со списком, а не несколько событий старта. Здесь вообще нет событий записи.

Любая ошибка/неполный обход, включая частичный положительный результат, даёт `unknown` с безопасной причиной. 401/403/429, сеть, redirect и невалидное тело не означают выход. Проверка прекращается при первой ошибке. До первой полной проверки — unknown/checking. После остановки — unknown/stopped, во время паузы — unknown/paused.

Свежесть ограничена 30 секундами от начала цикла, консервативно включая ожидание бюджета и все сетевые запросы. Слишком долгий полный цикл даёт unknown/stale. Getter `observation` также проверяет возраст предыдущего результата, пока следующий запрос ещё выполняется. Потребитель должен читать этот getter, не сохранять старое положительное/отрицательное значение как бессрочное. Ответы комнат не атомарный серверный снимок: API не гарантирует одновременность; reported presence — результат ограниченного по времени обхода. Отсутствие вне настроенного списка не утверждается.

Следующий цикл начинается через 10 секунд после завершения предыдущего (не чаще 2 секунд даже при инъекции интервала). Ошибки не создают параллельных циклов. Частый внешний `start()` идемпотентен.

## Отмена и время

`configure` всегда меняет generation, в том числе при равных значениях. Старые ответы после смены origin/ключа/комнат/user key не публикуются. Stop, pause, resume и restart также инвалидируют состояние/работу. Единственный worker отменяется; новое поколение ждёт его фактического завершения. Transport, игнорирующий отмену навсегда, блокирует дальнейший polling, а не создаёт новые висящие Tasks; старое состояние уже unknown. Сетевой URLSession имеет timeout 20 секунд, однако гарантия завершения неисправного backend не заявляется.

Clock монотонный ContinuousClock, включает время сна. В этой service-only части есть явные `pause`/`resume`; системные sleep/wake hooks должен подключить следующий runtime PR. До сна нужно pause, после пробуждения resume: до свежего опроса будет unknown. Даже без hook getter обнаруживает истёкшую свежесть. Реальный сон Mac этим PR не проверялся.

## Общий бюджет и секреты

Все default TalkAPIClient, включая профиль, используют один actor TalkRequestBudget. По одному origin он допускает запрос не чаще раза в 2 секунды, без начальной пачки, независимо от PAT. Это консервативнее ограничения на аккаунт и не позволяет сбросить бюджет заменой ключа. Для разных origin бюджеты независимы. Общее потребление других программ/других устройств учесть невозможно; 429 продлевает общий cooldown как минимум на минуту. Валидный более длинный Retry-After учитывается; форматы заголовка описаны в [RFC 9110, §10.2.3](https://www.rfc-editor.org/rfc/rfc9110.html#section-10.2.3). Спящие конкуренты заново проверяют бюджет при пробуждении; отменённый waiter не отправляет запрос. Бюджет хранится только в памяти процесса, после перезапуска не восстанавливается.

Сохранён прежний контракт: HTTPS origin, X-Auth-Token только в header, ephemeral URLSession без cookies/credential store/cache, redirect delegate отказывает перенаправлению. URL комнаты формируется из валидированного ID. Тела/URL-параметры/значения секретов не логируются; observer наружу отдаёт enum причины, не произвольный Error. Keychain остаётся в принятом слое подключения.

## Проверка и следующие границы

Synthetic URLProtocol проверяет транспорт, schema/identity и 429; управляемые clock/continuations проверяют частичные результаты, одноимённых участников, обе комнаты, свежесть, смену всех полей конфигурации, stop/restart, pause/wake и late reply игнорирующего отмену backend. Настоящий PAT/пространство/комната не использовались. UI не менялся и CUA не запускался.

Дальше отдельно нужны UI комнат и подтверждения аккаунта, включение режима и production hooks. API описывает аккаунт, не доказывает звонок на этом Mac. Способ локального подтверждения с выключенным mic/телефоном ещё надо согласовать до записи; наличие процесса/звук вне звонка не принимается за доказательство. Живые запросы и звонок требуют отдельного выбранного пользователем сценария. #3 остаётся открытым; main не меняется.

Авторская проверка: `make check` — 276 passed / 328 запусков с параметрами / 0 failures / 5 skipped. Пропуски: три native embedding/model opt-in и два UI-render opt-in; ASR E2E исключён. Один runtime QoS warning в DocumentFormatImportTests, compiler concurrency warnings в предсуществующих ASR/Library/Pipeline путях; новых warnings изменённых Talk-файлов нет. `git diff --check` успешно.
