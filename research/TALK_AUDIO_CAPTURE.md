# Системный звук только нативного Толка (#22, часть #3)

## Область

30 октября 2026 пользователь выбрал только нативное приложение «Толк». Браузеры не включаются. По документации Apple аудио ScreenCaptureKit фильтруется на уровне приложения, даже когда видео ограничено одним окном. Поэтому выбор окна/заголовка не является способом изолировать вкладку браузера.

Подтверждённые чтением Info.plist установленного клиента bundle IDs:

- kontur.talk;
- kontur.talk.helper;
- kontur.talk.helper.Renderer;
- kontur.talk.helper.GPU;
- kontur.talk.helper.Plugin.

Выбор точный, без расширения по префиксу. Основной kontur.talk обязателен; одни helper-процессы не заменяют клиент. Пустой список, некорректный PID и конфликт идентичности PID — ошибки. Неизвестные helper IDs исключаются; после обновления клиента список может потребовать пересмотра.

## Подключение

SystemAudioCaptureTrack получает SCShareableContent и выбирает приложения по селектору. SCContentFilter создаётся только через includingApplications с непустым списком выбранных объектов; exceptingWindows пуст. Общего display-фильтра и fallback на другие приложения нет. Заголовки окон не участвуют в фильтре. Видеокадры по-прежнему отбрасываются.

Перед стартом и после завершения startCapture проверяются выбранные процессы. Затем TalkAudioProcessGuard проверяет их раз в секунду. Список фиксирован для сеанса: если выбранный процесс завершился, его новый PID автоматически не подставляется. Удерживаются исходные NSRunningApplication, чтобы последующий экземпляр не оживлял старую выборку. Ошибка stream дополнительно проверяет источник, не дожидаясь следующего timer tick.

Потеря процесса или невозможность проверки вызывает существующий безопасный lifecycle: failed, финализация и preserveAudio=true. Общий системный захват не включается. Причина передаётся в состояние меню: нативный Толк не найден, источник исчез или источник недоступен. Тишина не участвует в проверке процессов.

Прежний автодетектор аудио/окон остаётся явно эвристическим. Этот фильтр не включает API-определение комнаты.

## Проверка

Unit-test host блокирует live-фабрику до обращения к ScreenCaptureKit/TCC. Тесты используют синтетические списки и backend, проверяют точный селектор, браузеры/похожие IDs/пустой список, неверные/конфликтующие PID, потерю helper, новый PID вместо старого, ошибки проверки, потерю процесса во время старта и во время записи, сохранение аудио и отсутствие fallback/автоматической замены источника.

Команда полного набора: TEST_RUNNER_GOLOS_MEET_MENU_PREVIEW=1 make check.

Для UI есть отдельный [synthetic harness](recording-menu-preview/README.md) с bundle id com.golos.talk-source-preview. В нём нет монитора процессов или аудиобэкенда; он использует реальные классы меню и тексты ошибок. Три открытых native popup проверены через accessibility; снимки CUA показывают окно harness без popup-слоя, поэтому визуальная проверка этого слоя требует отдельного подтверждения reviewer.

## Непроверенное

Реальный stream/исключение звука других приложений, TCC, поведение helper-процессов на реальном звонке, mute, сон/пробуждение, качество и синхронизация дорожек не проверены. Фильтр задаёт приложение целиком: собственные уведомления/другие окна Толка не отделяются от конкретной встречи. Нет обещания захвата отдельного звонка или вкладки. Проверка процесса имеет интервал до следующего poll; сам фильтр при этом остаётся фиксированным включающим списком.

Ограничения навсегда зависшего start и неподтверждённой физической остановки при ошибке stopCapture остаются из #17. Отложенный выбор отменён: пользователь выбрал PAT/комнаты/подтверждение аккаунта и звонки только с этого Mac; API-only runtime описан в [TALK_API_RECORDING.md](TALK_API_RECORDING.md). Mic activity не является условием участия; #3 целиком не закрывается.
