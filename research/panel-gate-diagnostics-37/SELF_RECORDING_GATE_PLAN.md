## Один самопишущий сценарий, один consent

1. Host logger действует с начала процесса и имеет sessionUUID, строго возрастающий event sequence, monotonic+UTC, bounds каждого async snapshot. Append-only local JSONL с flush/error handling. Logger привязан к **реально показанному entry/model**: factory присваивает entryUUID/modelObjectID, регистрирует weak observation actual returned model и appearance/disappearance. Старый `state.model` остаётся отдельно помечен hidden, не используется для verdict.
2. Одна host-only кнопка **«Подготовить контроль удержания»** делает `await gate.arm()` и получает armToken ACK. Только после завершения actor arm и сохранения durable event показывает **«Удержание готово · token…»**. Простой клик без ACK не считается armed. Не менять кнопки/guards actual panel. Human открывает actual project route/preview, читает его и даёт единственное согласие существующей production кнопкой, без переписки между timed действиями.
3. Связать model/requestUUID с последним приготовленным preview. Host-only synchronous observation actual model `$request`/`$busy` фиксирует переход prepared request→nil при busy=true как **observed send-state marker**, не как raw mouse click. До реализации отдельно проверить синхронность @Published sink и точное source ordering `send`: request=nil происходит до создания operation Task/approve/process/timer. Cancellation path busy=false не должен ошибочно называться consent. Если такой marker нельзя доказать без production изменений — использовать непрерывные свежие full SQL needsConsent snapshots; не подменять их last traceCalls0.
4. Fake adapter записывает callUUID/request binding, **held-waiter-registered(token)** до видимого ACK **«Вызов1 действительно удерживается — выберите Приватный»**. Только после реального continuation registration такой label разрешён. Calls1 без waiter не считается held. Регистрация/счётчики/trace одной сессии; конкретный armToken связывает setup и эту физическую отправку. Нет автоматического consent, no retries/fallback.
5. Человек переключает **actual panel Picker** на «Приватный» по локальной инструкции в том же окне. Host наблюдает именно этот model.projectID transition с entryUUID, requestUUID/callUUID и timestamp; не меняет projectID программно вместо UI. Внешний chat timeout больше не участвует. UI показывает локальную phase/countdown, основанную на валидном pre-process marker/SQL anchor, а не на позднем fake-call timestamp.
6. Встроенный bounded observer сохраняет actual DB job/attempt/generation/input/cycle/state и history snapshot до consent, при held ACK, при project change и до release; каждый SQL read atomic внутри своей транзакции. Root выбирает тот же консервативный критерий cancelled END<20s от валидного pre-process marker/замороженного needsConsent anchor. Изменившиеся identity, missed running, unrelated reset, partial log, overflow, read error → red INCONCLUSIVE, никогда не Passed.
7. **Release автоматизировать только в diagnostic coordinator ПОСЛЕ сохранённого earlycancel**, не требовать от человека чтения Terminal/чат-команды. Логировать release-request/actor-release/adapter-physical-return и callUUID. До этого не должно быть release. Затем actual worker/service завершают поздний ответ; сохранить неизменные history0/calls1/отсутствие late publication. `worker.waitUntilIdle()` сам по себе не physical join approval: у него цикл по worker Task, тогда как explicit approval может иметь active task отдельно; обязательны adapter-return и завершение owned model operation либо иной доказанный receipt. Не добавлять production hook ради этого.
8. Локальная фаза просит **«К проекту»→«Память»**; логировать host onBack/entry disappear/new entryUUID/appear и weak old model lifetime. Новый entry не содержит old preview/consent; один explicit retry/prepare допускается только до нового preview, без второго consent/call. Сохранить final snapshot/manifest SHA; не объявлять source audit normal singleton composition живым runtime.

## Ограничения и cleanup

Один build, один host, один actual held attempt; не матрица. Предлагаемый build budget180s, output budget1GiB, preflight free>=6GiB с STOP ниже6GiB; никаких full/OCR/новых weights. Diagnostic capture: <=512events/2MiB, подготовка до5мин (без send), actual case<=45s; общий watchdog не изменяет продуктовые30s. Пока человек читает preview, не расходовать20s cancellation budget. После recorded send отдельный20s proof budget. При timeout/overflow/write error UI ясно показывает red, действия сценария выключены; cleanup получает отдельную phase, снимает только собственную fake continuation и завершает owned tasks. Любой cancel/release, сделанный только для cleanup, не засчитывать доказательством project switch. Не forcecloseSQLite/retainallroots; root удаляет лишь свой host после сохранённых actual close/proof отдельно.

У существующего host logger trace не имеет timestamps/armACK/release/physical-return. `PanelPreviewRoot.onChange(model.heads/request)` смотрит **hidden state.model**, а `ProjectMemoryEntry(...makeModel:state.panelModel)` создаёт новый actual model. Поэтому heads1 не говорит, какой проект был выбран в видимой панели, а factory-record сообщает только начальные аргументы. Новый logger обязан хранить эту границу и слабое ownership; дополнительный strong observer не должен искусственно продлевать old entry lifetime.
